### Подробнее по важным

**1. Ранжирование CommentRadar.** Расхождение с ТЗ: раздел 4 требует
«отсортированный список по релевантности и свежести». Локальный режим это
делал, облачный выдавал ленту в порядке сервера. Считаю на клиенте той же
функцией движка, что и локальный режим — два режима дают одинаковый
порядок, API не нужен.
*Проверено:* обсуждения про «ревью» поднялись наверх со 100 % и 85 %.

**2. Архив постов.** Пункт ТЗ раздела 3 и стандарт рынка. В API группа
была целиком — в интерфейсе не было ни одного вызова `api.posts.*`.
*Проверено:* добавил пост формой, список обновился, импорт отработал
и показал отчёт.

**3. Правила голоса.** Writer разделяет Brand Voice и Brand Rules;
у нас карточка была только для чтения. Это закрывает открытый пункт
README: «интерфейс настройки правил AntiCringe не реализован».
**Важно:** `POST /tov/analyze` обнуляет `stop_words` — повторный разбор
стирал бы ручные правила. Клиент их запоминает и возвращает отдельным
`PUT`, автору это показывается. Правильное место для логики — сервер,
запрос напарнику в разделе 5.
*Проверено:* стоп-слова «синергия», «драйвить» пережили повторный разбор.

**10. История версий (единственная функция на моках).** Снимок текста
перед каждым сохранением, просмотр версии, обратимый возврат (текущий
текст сам становится версией). Контракт — раздел 5.
*Проверено:* дописал абзац → «Версия 1, 294 символа, −119 к текущему» →
возврат → текущий стал «Версией 2», редактор вернулся к 294 символам.

## 5. Контракт API для напарника

### 5.1. Новая группа: версии черновика (сейчас на моках)

Таблица `draft_versions`:

| Поле | Тип | Правило |
|---|---|---|
| `id` | bigint | первичный ключ |
| `draft_id` | bigint | FK → `drafts.id`, **ON DELETE CASCADE** |
| `version` | int | `unique (draft_id, version)` |
| `text` | text | снимок до правки, неизменяем |
| `title` | text | название на момент снимка |
| `origin` | enum | `author` / `narrative_engine` / `autofix` |
| `created_at` | timestamptz | — |

Индекс `(draft_id, created_at desc)`. Не больше 30 версий на черновик.

- `GET /drafts/{draftId}/versions` — `?limit=`, `?cursor=` → `{ items, next_cursor }`,
  элемент: `{id, draft_id, version, text, title, origin, chars, created_at}`
- `POST /drafts/{draftId}/versions` — `{text, title, origin}` → `201`.
  **Лучше делать это внутри `PATCH /drafts/{id}`.** Если текст совпадает
  с последней версией — `200` и та же версия, без создания новой
- `GET /draft-versions/{id}` → `200`
- `POST /draft-versions/{id}/restore` → `{ draft, restored_from }`.
  **Перед заменой сервер обязан сохранить текущий текст новой версией**,
  иначе возврат необратим
- `DELETE /draft-versions/{id}` → `204`

Права — как у `drafts`: чужое даёт `404`.
Фронтенд обрабатывает: `404 not_found`, `422 unprocessable`,
`401 unauthorized`, недоступность сети.
Использует только шаг 3 «Черновик».

### 5.2. Две правки в существующем

**`POST /tov/analyze` затирает ручные стоп-слова.** Метод делает upsert
профиля целиком и ставит `stop_words: []`. Просьба: сохранять их при
разборе — разбор их не вычисляет, значит и не должен обнулять.
Сейчас это обходит клиент, десять строк удалятся.

**`stop_words` и `slang` не доходят до движка.** Их не читает ни правиловый
AntiCringe (`toEngineProfile`), ни промпты LLM. Автор заполняет стоп-слова,
а проверка их не замечает. Просьба: передавать `stop_words` в AntiCringe
отдельной группой замечаний (тип `tov`, severity `medium`, цитата —
найденное слово) и в системный промпт как запрет; `slang` — наоборот,
как разрешённые слова.

### 5.3. Чего не хватало, но обошлись

Ранжирование ленты считаю на клиенте — серверная сортировка не нужна.
Скрытие чеклиста храню в `localStorage` — поля в базе под это не прошу.

## 6. Решения, которые я принял сам

1. **Ранжирование CommentRadar на клиенте**, а не новым параметром API —
   два режима дают одинаковый порядок, откатывается удалением одного файла.
2. **Стоп-слова возвращаю клиентом после разбора.** Альтернатива —
   запретить повторный разбор — хуже: он нужен после каждой пачки постов.
3. **Удаление канала — в модалке настроек**, подтверждение словом только
   для удаления аккаунта: канал удаляют осознанно и нередко, аккаунт — раз.
4. **Чеклист только на «Конвейере»** — иначе повторялся на всех пяти
   разделах; заодно пересчитывается при возврате.
5. **История версий — единственная функция на моках.** Планировщик и
   аналитика тоже стандарт рынка, но ТЗ выносит их за границы проекта.
6. **Склейка одновременных GET вместо кэша** — кэш требует инвалидации,
   а так четыре одинаковых `GET /tov` схлопнулись в один.
7. **Демо-данные завёл через HTTP API, а не `npm run db:seed`** — сид
   пишет в базу напрямую, это за границами задачи.
8. **Карточка Tone of Voice — один компонент**, а не два выровненных:
   иначе они разойдутся снова при первой правке.
9. **Шрифты с Google Fonts ссылкой**, системный стек в запасе.
10. **Режим по умолчанию — облачный.** Локальный остаётся и подхватывается
    сам, если сервер недоступен.
