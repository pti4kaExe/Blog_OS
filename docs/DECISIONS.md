# Журнал решений BlogOS — целевая версия

Документ закрывает все пункты «Нужно уточнить» из ТЗ v1.1 и открытые вопросы
документа «Структура базы данных и методы сервиса». Формат: решение, чем
обосновано, что меняется, если решение пересмотрят.

Версия 2.0 · собрано по итогам согласования с заказчиком.

---

## Согласовано с заказчиком

| № | Вопрос из ТЗ | Решение | Обоснование и последствия |
|---|---|---|---|
| 1 | Какой хостинг и провайдер базы (раздел 10) | **Neon** (free tier) — PostgreSQL 16 + pgvector; локально `docker compose` с образом `pgvector/pgvector:pg16` | Бесплатный тариф, pgvector включён, ветвление БД для миграций. Ограничение free: база засыпает после простоя — первый запрос после паузы медленнее, `healthcheck` это переживает |
| 2 | Хостинг сервера (раздел 10) | **Render** (free web service), конфигурация в `render.yaml` | Бесплатный тариф засыпает через 15 минут простоя и просыпается ~30–60 с. Для демонстрации прогрев обязателен: `GET /health` перед показом |
| 3 | Хостинг клиента (раздел 10, «Публикация на Netlify») | **Vercel** (free), конфигурация в `vercel.json`; Netlify остаётся рабочим вариантом — сборка статическая | Требование заказчика — бесплатный хост. Клиент — статика, ограничений по тарифу почти нет |
| 4 | Кэш и очереди | **Upstash Redis** (free) — только для ограничения частоты сканирований; без `REDIS_URL` работает in-memory ограничитель | Redis не обязателен: раздел 4 документа по БД называет его «не основной базой». Отказ Redis не ломает функции |
| 5 | Модель эмбеддингов и N (раздел 7, блокирует схему) | **text-embedding-3-small, `vector(1536)`** | N зафиксирован в DDL. Смена модели = миграция колонки `embeddings.embedding` + пересчёт всех векторов; поле `model` в таблице показывает, что пересчитывать. В локальном режиме `EMBEDDINGS_PROVIDER=mock` даёт детерминированные векторы той же размерности — тесты и демо идут без сети |
| 6 | Провайдер и модель LLM (разделы 8, 10) | **DeepSeek (`deepseek-chat`)** как основной, OpenAI (`gpt-4o-mini`) как альтернатива, `mock` по умолчанию для локальной разработки | Дешёвые вызовы; API совместимо с форматом OpenAI, поэтому один адаптер закрывает оба провайдера. Ключ — только в переменных окружения сервера, в клиент не попадает |
| 7 | Поведение при превышении `monthly_cost_limit` (раздел 11) | **80% — мягкое предупреждение, 100% — AI-вызовы блокируются, движок откатывается на правила** | Ответ `GET …/usage` отдаёт `warning`/`blocked`; при блокировке `lint`/`generate` отвечают с `verified_without_ai: true`, а вызов LLM не выполняется. Автор никогда не остаётся без проверки текста |
| 8 | Объём площадок (раздел 3) | **Telegram, Instagram, YouTube — реальные адаптеры импорта и сканирования**; заказчик расширил объём против ТЗ v1.1 | Против ТЗ v1.1 это расширение, поэтому площадки изолированы в `adapters/`: отказ или отсутствие ключей площадки не ломает остальные функции (`503 not_configured`). Условия API Instagram (Business-аккаунт, доступ приложения) и YouTube (квота) проверяются до продакшена — в ТЗ это оставалось открытым |
| 9 | `tov_profiles` — 1:1 или 1:N (открытый вопрос документа по БД) | **1:1**, уникальный `author_id` | Как в ТЗ («один профиль на канал»). Разные площадки — разные каналы, значит разные стили и так |
| 10 | Связь `embeddings` ↔ `knowledge_base` (открытый вопрос документа по БД) | **Ровно один владелец**: `CHECK ((post_id IS NOT NULL)::int + (knowledge_id IS NOT NULL)::int = 1)` | Закрывает «нужно поле связи в embeddings». Вектор не может одновременно ссылаться на пост и на факт |
| 11 | Поля `generation_runs`, `golden_dataset`, `knowledge_base` (в ER-схеме не было) | Собраны по описанию сущностей ТЗ и подтверждены миграцией | `generation_runs`: `task_type, model, tokens_input, tokens_output, tokens, cost, status, error_message, duration_ms`; `golden_dataset`: `text, labels, platform`; `knowledge_base`: `title, content` |
| 12 | Вход и запуск (раздел 2) | **Telegram `initData` + dev-вход** через тот же метод при `DEV_AUTH=1` | Проверка подписи HMAC-SHA256 по токену бота. Без бота проверяющий запускает локально и входит dev-методом; на проде `DEV_AUTH=0` и ветка отключена |
| 13 | Формат и ограничения файла для `POST /posts/import` (раздел 6) | Файлов нет: импорт по `source_url` площадки. Формат передачи — JSON, ограничение `limit ≤ 200` | В ТЗ формат не зафиксирован; текстовый импорт по ссылке не требует загрузки файлов, а границы проекта запрещают придумывать лишнее |
| 14 | Интерфейс настройки правил AntiCringe (раздел 3) | **Не реализуется сейчас.** Сервер хранит `tov_profiles.stop_words` — этого достаточно для настраиваемых стоп-слов; отключение групп правил остаётся открытым | Функция помечена «Нужно уточнить» в ТЗ, интерфейс не описан. Реализация по догадке нарушила бы правило «функции без описания не придумываются» |
| 15 | Календарные даты трёх этапов (раздел 14) | Вне кода: план из трёх недель остаётся в ТЗ, чат с преподавателем | Код от дат не зависит |

## Технические решения (приняты при реализации)

| № | Решение | Почему так |
|---|---|---|
| 16 | **Стек сервера: Node.js 20 + TypeScript + Fastify 5 + `pg` (без ORM)** | Заказчику нужен бесплатный хост: Fastify лёгкий и холодный старт на Render быстрее, чем у Express+Nest. ORM не взят сознательно: `vector(1536)` и HNSW-поиск живут только в сыром SQL, а Prisma не создаёт `Unsupported`-колонки миграциями — получилось бы два источника истины (схема Prisma и DDL). DDL в `db/sql` — единственный источник, запросы — типизированные репозитории |
| 17 | **Движки остаются чистыми функциями в `packages/engine`** | ТЗ, раздел 8: «интерфейс `lint(text, profile)` не меняется, нейросеть становится вторым источником замечаний». Один пакет используют и браузер (мгновенные Шаги 1—4), и сервер (первый слой и откат). 49 тестов остаются в силе |
| 18 | **Клиент работает и без сервера** | Прототип из раздела 1 ТЗ сохраняется как режим «локально»: если API недоступен, конвейер и CommentRadar считаются в браузере, данные — в `localStorage` (`blogos.state.v1`). Это и демонстрация без сети, и честный офлайн-режим |
| 19 | **`lint_reports` неизменяемы на уровне базы** | ТЗ, раздел 7: «неизменяемые после создания». Триггер `blogos_forbid_update` не даёт `UPDATE`; история проверок — цепочка записей |
| 20 | **`generation_runs` переживает удаление канала** | ТЗ, разделы 4 и 7: `ON DELETE SET NULL`. Иначе удаление автора стирало бы историю расходов |
| 21 | **`drafts.published_post_id` — `SET NULL`** | ТЗ, раздел 4: удаление опубликованного поста не удаляет черновик |
| 22 | **Триггер `updated_at` на всех изменяемых таблицах** | Даты не расходятся с реальностью, даже если сервер забыл поле |
| 23 | **JWT в `Authorization: Bearer`, срок жизни 30 дней** | Не нужна отдельная таблица сессий (схема зафиксирована на 14 таблиц). Отзыв — сменой `JWT_SECRET`; границей риска пренебрегаем осознанно для проекта такого размера |
| 24 | **Курсорная пагинация по `(created_at, id)`** | ТЗ, раздел 8: `limit` 50/200 и `cursor`. `OFFSET` на бесплатной базе деградирует, курсор — нет |
| 25 | **`mock`-провайдеры LLM и эмбеддингов включены по умолчанию** | Тесты, демонстрация и CI работают без ключей и денег; реальные провайдеры включаются переменной окружения. Это же делает проверяемым требование «откат на правила» |
| 26 | **Ошибка площадки после одной повторной попытки — явная ошибка, не тихий сбой** | ТЗ, разделы 8 и 11. `sources.last_scan_status`/`last_scan_error` хранят результат — автор видит дату последнего успешного сканирования |
| 27 | **Публикация черновика не отправляет пост на площадку** | Границы проекта (ТЗ, раздел 3): BlogOS не публикует от имени автора. `POST /drafts/{id}/publish` только фиксирует публикацию в архиве |
| 28 | **Приватность: предупреждение перед первым AI-вызовом** | ТЗ, разделы 8, 11, 12: модель получает тексты автора. Флаг `ai_consent_at` в `users`… — **не добавлен**: схема зафиксирована на 14 таблицах, поэтому согласие хранится на клиенте (`localStorage`) и передаётся как `use_llm: false` при отказе. Открытый пункт для следующей версии схемы |
| 29 | **Проверка прав — в репозиториях, а не в роутерах** | Один источник проверки «своё/чужое»: каждая выборка фильтруется по владельцу, поэтому забыть guard в новом методе сложнее |

## Что осталось открытым (и почему это не блокирует)

| Вопрос | Статус | Что нужно, чтобы закрыть |
|---|---|---|
| Условия Instagram Graph API и YouTube Data API | Адаптеры написаны, живые ключи не проверены | Business-аккаунт + приложение Meta; ключ YouTube Data API и квота |
| Срок хранения запросов у поставщика LLM | Требование «провайдер без обучения на данных» зафиксировано | Прочитать условия DeepSeek/OpenAI до продакшена и вписать сюда |
| Стоимость вызова и тариф | Считается по прайсу провайдера в `pricing.ts` | Сверить прайс при подключении ключа |
| Хранение согласия на передачу текста наружу | Клиентское (`localStorage`), в схеме поля нет | Миграция `users.ai_consent_at` — следующая версия схемы |
| Интерфейс настройки правил AntiCringe | Не реализуется (см. № 14) | Дизайн-эскиз от заказчика |
| Форматы импорта файлов | Не нужны: импорт по ссылке (см. № 13) | — |
