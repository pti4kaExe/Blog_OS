# Функция (следующий шаг): AI-подсказки замены запрещённых слов

**Статус:** промт и план проверки готовы, в интерфейс не подключено.
**Откуда идея:** отзыв преподавателя — «функция работает без ИИ, но нейросеть
может предлагать синонимы для запрещённых слов».

## Зачем это в продукте

Правило AntiCringe сейчас говорит «нельзя»: показывает слово и объясняет, почему.
Это правильно, но автор остаётся один на один с задачей «а как сказать иначе».
Нейросеть как раз хорошо делает то, что правилам недоступно: подбирает замену
**в конкретном контексте и в голосе автора**.

Важно, что функция остаётся дополнением, а не заменой:

- правило срабатывает **всегда** и без ИИ (это инвариант продукта);
- подсказки замены — **опциональный слой**: только при согласии на AI, только по
  запросу автора, с расходом из лимита канала;
- если AI недоступен или лимит исчерпан, кнопка честно сообщает, что подсказки
  сейчас недоступны, а проверка продолжает работать на правилах.

## Промт

### Системный промт

```
Ты — редактор текстов для автора блога. Твоя задача: заменить указанное «запрещённое» слово или оборот в предложенном контексте и предложить 3–4 альтернативы.

Правила:
1. Смысл предложения не меняется. Не добавляй факты, цифры, примеры и выводы, которых не было в исходном тексте.
2. Заменяй именно запрещённый фрагмент, а не переписывай предложение целиком: остальные слова автора сохраняются.
3. Альтернативы должны звучать как живая речь автора, а не как официальный документ. Разные варианты — разная стратегия: короче, разговорнее, конкретнее, без оценочности.
4. Запрещённое слово и его однокоренные формы не должны появляться ни в одной альтернативе.
5. У каждой альтернативы — короткая причина (до 8 слов), зачем она нужна.
6. Если заменить фрагмент нельзя без потери смысла — верни пустой список альтернатив и укажи причину в "needs_rewrite".

Ответ строго в JSON без markdown:
{
  "alternatives": [
    { "text": "полное предложение с заменой", "why": "почему так" }
  ],
  "needs_rewrite": false,
  "reason": ""
}
```

### Пользовательский промт (шаблон)

```
Запрещённое слово или оборот: «{{word}}»
Контекст (предложение, где он встретился): «{{sentence}}»
Как пишет автор: {{style}}
{{#if paragraph}}Абзац целиком для понимания: «{{paragraph}}»{{/if}}

Предложи 3–4 альтернативы по правилам.
```

Слоты:

| Слот | Откуда берётся | Зачем |
|---|---|---|
| `word` | цитата замечания `tov:stopword` | что именно запрещено |
| `sentence` | предложение из черновика, где стоит цитата | замена должна подойти грамматически |
| `style` | профиль стиля: обращение «ты/вы», средняя длина фразы, любимые обороты | чтобы не звучало как пресс-релиз |
| `paragraph` | абзац, если предложение короткое | контекст без переписывания всего текста |

### Параметры вызова

| Параметр | Значение | Почему |
|---|---|---|
| `temperature` | 0.5 | нужна вариативность вариантов, но не «творчество» |
| `max_tokens` | 1200–2000 | один абзац JSON; больше не нужно |
| Формат ответа | JSON | разбирается строго, без «вот варианты:» в прозе |
| Повторы | 1 повтор при сетевой ошибке | как у остальных AI-вызовов |
| Расход | запись в `generation_runs`, `task_type = 'synonyms'` | лимит канала учитывает подсказки |

## Почему промт сформулирован именно так

1. **«Полное предложение» в ответе, а не слово.** Замена слова требует
   согласования падежа: «синергию» → «взаимодействие между» уже меняет
   управление. Просить готовое предложение — надёжнее, чем склеивать на клиенте.
2. **Запрет на «остальное перепиши».** Иначе модель переписывает весь текст и
   автор теряет свои формулировки. Отдельно проверяем это в коде: сравниваем
   предложение с оригиналом и отбрасываем варианты, где изменено слишком много.
3. **Запрет на новые факты.** Главный риск генерации — выдуманные цифры и
   примеры. Правило 1 + пост-проверка «нет чисел, которых не было в оригинале».
4. **Три разные стратегии вместо трёх синонимов.** Автору полезнее выбор
   «короче / разговорнее / конкретнее», чем три варианта одного слова.
5. **`needs_rewrite`.** Честный выход: иногда фразу нельзя заменить, не поменяв
   мысль. Тогда лучше сказать это, чем подсунуть кривую замену.

## Пост-проверки результата (в коде, а не в промте)

Ответ модели принимается, только если:

1. JSON разобран, альтернатив 3–4;
2. в варианте нет запрещённого слова и его форм (сравнение по основе — та же
   функция, что в правиле `tov:stopword`);
3. предложение сохранило начало и конец (изменения локализованы вокруг цитаты);
4. в варианте нет новых чисел и имён, которых не было в оригинале;
5. каждое поле `text` — одна строка, длиной до 400 символов.

Не прошло — вариант отбрасывается. Если отброшены все — интерфейс говорит
«не удалось предложить замену», а не показывает мусор.

## Как это выглядит в интерфейсе

На замечании «Запрещённое слово» появляется кнопка **«Предложить замену»**:

1. нажатие отправляет слово и предложение на сервер;
2. под замечанием появляются 3–4 карточки: текст замены, причина, кнопка
   «Применить»;
3. «Применить» заменяет фрагмент в черновике, проверка запускается заново;
4. если AI выключен (нет согласия или лимит) — кнопка не показывается, вместо неё
   строка «Подсказки замены доступны с включённым AI-слоем».

Правило при этом работает всегда — это не меняется.

## Как проверить промт (до кода)

В репозитории есть скрипт `scripts/experiments/synonyms-prompt.mjs`: он берёт
промт, гоняет его на четырёх случаях и проверяет ответ автоматически.

```bash
node scripts/experiments/synonyms-prompt.mjs
```

Скрипт печатает для каждого случая: время ответа, число альтернатив, сам текст,
причину и предупреждения (запрещённое слово осталось, изменено слишком много,
появилось новое число).

Случаи подобраны так, чтобы ломать промт по-разному:

| Слово | Чем сложен |
|---|---|
| «синергия» | абстрактное существительное, падеж должен совпасть |
| «в современном мире» | оборот-клише, замена меняет структуру предложения |
| «лидер рынка» | утверждение про себя, легко скатиться в оценочность |
| «оптимизировать» | термин, замена должна быть человеческой, не канцелярской |

## Критерии оценки (по ним же — приёмка фичи)

| Критерий | Как проверяем |
|---|---|
| Смысл сохранён | сравнение с оригиналом: ключевые слова и числа не изменились |
| Нет запрещённого слова | пост-проверка по основе |
| Не переписан весь текст | начало и конец предложения совпадают с оригиналом |
| Похоже на голос автора | ручная оценка 1–5 на 4 случаях, среднее ≥ 3.5 |
| Нет выдуманных фактов | пост-проверка на новые числа и имена |
| Быстро | ответ ≤ 20 с (цель), ≤ 60 с допустимо на бесплатной модели |

## Что уже готово и что нет

- готовы: промт, шаблон слотов, пост-проверки (описаны), скрипт эксперимента,
  критерии приёмки;
- не готово: эндпоинт API, подключение к интерфейсу, запись расхода в журнал,
  mock-ответ для тестов без сети.

Это следующий блок плана (7.2). Реализация — после того как промт прогонит автор
на живой модели локально (из песочницы, где писалась фича, OpenRouter блокирует
запросы по IP, поэтому живые ответы модели здесь недоступны).
