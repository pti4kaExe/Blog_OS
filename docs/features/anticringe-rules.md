# Функция: правила AntiCringe

**Блок плана:** 7 · **Дата:** 11 ноября 2026 · **Статус:** готово

## Задача

Проверка AntiCringe знала общие списки клише и канцелярита, но не знала, что
неприемлемо **именно для этого канала**. Автор мог видеть в отчёте «всё чисто»,
хотя в тексте есть слово, которое он сам себе запретил: «синергия», «в
современном мире», «лидер рынка», название чужого продукта.

Нужен способ сказать инструменту: «вот эти слова и обороты у меня не пишем» —
и чтобы проверка их отмечала.

## Что делает функция

В настройках канала появляется блок **«Правила AntiCringe»**:

- список запрещённых слов и коротких оборотов (до 50 правил);
- добавление, удаление, сохранение — как обычный список тегов;
- при проверке черновика каждое совпадение становится отдельным замечанием в
  категории Tone of Voice: цитата, объяснение, место в тексте.

Свойства, важные для продукта:

| Свойство | Почему так |
|---|---|
| Работает **без AI** | Правило — это решение автора, модель для него не нужна. Проверка не должна зависеть от расходов на AI и от доступности провайдера |
| Учитывает **словоформы** русского языка | «Синергия» в правиле должно поймать «создаём синергию». Сравнение по основе, а не по точной строке |
| Одинаково в **локальном и облачном** режиме | Правило живёт в общем пакете движков, который используют оба режима |
| Хранится **в профиле канала** | Профиль стиля уже 1:1 с каналом, и правило — часть редакторских настроек канала, а не глобальная настройка аккаунта |

## Как это устроено

```
настройки канала → PUT /author-profiles/{id}/tov   (stop_words: [...])
                          │
                          ▼
        tov_profiles.stop_words (PostgreSQL, JSONB-поле профиля)
                          │
        ┌─────────────────┴──────────────────┐
        ▼                                    ▼
 сервер: toEngineProfile()            браузер: engineProfileFromTov()
        └──────────────┬───────────────────┘
                       ▼
        packages/engine → правило tov:stopword
                       ▼
        отчёт проверки: замечание с цитатой и диапазоном в тексте
```

Изменения в коде:

| Слой | Файл | Что сделано |
|---|---|---|
| Движок | `packages/engine/src/anticringe.js` | Правило `tov:stopword`: сравнение по основе для слов, поиск подстрокой с границами для оборотов |
| Клиент | `apps/web/src/lib/tov.js` | `stopWords` в профиле, который получает движок |
| Клиент | `apps/web/src/components/cloud/AntiCringeRules.jsx` | Панель «Правила AntiCringe» |
| Клиент | `apps/web/src/components/cloud/SettingsView.jsx` | Карточка в настройках канала |
| Сервер | `apps/api/src/services/style.ts` | `stopWords` в профиле проверки |

Схема БД **не менялась**: поле `stop_words` было в `tov_profiles` с самого начала,
его просто никто не читал при проверке.

## Как проверить (2 минуты)

1. Открыть настройки канала.
2. В блоке «Правила AntiCringe» добавить правило: `синергия`.
3. Сохранить.
4. На шаге «Заметки» собрать черновик, в котором есть фраза «создаём синергию».
5. На шаге «Проверка» запустить проверку.
6. В отчёте — замечание «Запрещённое слово» с цитатой «синергию».
7. Удалить правило в настройках и повторить проверку: замечания больше нет.

## Что проверено тестами

- движок: словоформа («синергия» → «синергию»), оборот целиком, группа Tone of
  Voice, пустой список правил, работа без профиля, короткое слово «не» не
  срабатывает внутри «неделя» — **6 проверок**;
- API: правила, сохранённые в профиле, попадают в отчёт проверки черновика —
  **1 тест**;
- клиент: сборка и серверный рендер экрана настроек.

## Найденные по ходу ошибки

1. **Правило было «мёртвой» настройкой:** панель сохраняла список, но движок его
   не читал — проверка ничего не отмечала. Исправлено добавлением правила в
   движок и маппинга поля в профиль.
2. **Словоформы не ловились:** точное совпадение строки не находило «синергию»
   по правилу «синергия». Исправлено сравнением по основе.

## Ограничения и следующий шаг

- Нет автозамены и регулярных выражений: правило только отмечает, решает автор.
- Нет «общих» правил на все каналы: список привязан к каналу.
- Следующий шаг — переносить частые правила в локальный словарь канала, чтобы не
  вводить одно и то же вручную.
