# Жёсткое ревью BlogOS: дизайн, бэкенд, юзабилити, безопасность

**Дата:** 11 ноября 2026. Два независимых аудита (дизайн/UX и бэкенд/безопасность)
по исходникам, плюс самопроверка ключевых мест. Ниже: что нашли, что исправили,
что осталось и почему.

Полная инструкция «как проверить и сломать» — [`SECURITY.md`](SECURITY.md).

---

## 1. Холодный старт: убрали ожидание

**Было:** Render free засыпает после ~15 минут без запросов → первый посетитель
ждал 30–60 секунд, иногда видел «сервер недоступен».

**Что сделали:**

- `/health?light=1` — проверка живости без обращения к базе (не будит Neon, у
  которого свой лимит вычислений);
- workflow `Keep API warm` — пинг раз в 10 минут (`.github/workflows/keep-alive.yml`),
  бесплатно и без внешнего сервиса;
- `preconnect` к API в HTML и прежнее ожидание пробуждения в интерфейсе
  (страница сама дожидается до 80 с, показывая прогресс);
- раздел в `RUNBOOK.md` о том, как сузить окно прогрева, если подойдёт к лимиту
  750 часов инстанса.

**Альтернативы, если понадобится переезд:** Vercel serverless (нет сна, но лимит
длительности функций и перенос Fastify), Oracle Cloud always-free VM (полноценный
сервер, нужна карта для верификации), Cloudflare Workers (требует переписывания
API). Остаёмся на Render + прогрев — это дешевле всего в поддержке.

## 2. Безопасность: что исправлено

| # | Находка | Severity | Исправление |
|---|---|---|---|
| 1 | `monthly_cost_limit` по умолчанию `NULL` → AI-вызовы не ограничены, ключ владельца можно тратить циклом | Critical | Лимит по умолчанию 100 ₽ (`DEFAULT_MONTHLY_COST_LIMIT`), backfill старых каналов миграцией 005, минутная квота `AI_CALLS_PER_MINUTE=10` на канал |
| 2 | Ключи площадок попадали в `sources.last_scan_error` вместе с URL | High | `sanitizePlatformError`: вырезаются query-параметры и токены перед сохранением и показом |
| 3 | Код входа можно было обменять на JWT многократно; TTL 10 минут | High | Одноразовая выдача (`claimCode`, статус `used`), TTL 5 минут, миграция 004 |
| 4 | Поддельный `X-Forwarded-For` обходил лимиты | High | Доверяем только ближайшему прокси (функция `trustProxy`), ключ лимита — реальный IP |
| 5 | `DEV_AUTH` по умолчанию включён — потеря переменной открывала dev-вход на проде | High | Дефолт `false`; на проде сервис **не стартует** с `DEV_AUTH=1` |
| 6 | Потеря подтверждений `/start` при каждом деплое | Medium | `drop_pending_updates: false` |
| 7 | `/health` раскрывал провайдеров и конфигурацию | Medium | Отдаём только статус, базу, версию и флаги входа |
| 8 | Нет общего лимита запросов, нет таймаутов, тело 1 МБ | Medium | Общий лимит 240/мин на IP, тело 512 КБ, заголовки безопасности на всех ответах |
| 9 | `render.yaml` расходился с продом, Pages деплоился с рабочей ветки фронтенда | Medium | Blueprint синхронизирован (Telegram, публичные адреса, автомиграции), деплой только с `main` |
| 10 | TLS к Neon без проверки сертификата | High | Флаг `DB_SSL_VERIFY` (по умолчанию выключен — включать осознанно, см. SECURITY.md) |
| 11 | Нет проверки сертификата/схемы ответа и лимитов длины полей | Medium | Записано в остаточные риски: лимиты длины полей — следующий шаг |

**Что проверено тестами:** заголовки безопасности, CORS (свой/чужой origin),
общий лимит и исключение `/health`, огромное тело, одноразовость кода,
`/health?light=1`. Всего 122 теста API (было 114).

**Что осталось известным риском:** login CSRF через бота (нужен код
подтверждения), отсутствие отзыва JWT, CSP на GitHub Pages, лимитер в памяти,
проверка TLS к базе выключена по умолчанию. Все перечислены в `SECURITY.md`
с планом лечения.

## 3. Дизайн и юзабилити: что исправлено

| Приоритет | Что было | Что стало |
|---|---|---|
| **P0** | «Удалить канал» в модалке любого канала удалял **активный** канал — можно было потерять не тот | Отдельное состояние `deleteTarget`: подтверждение удаляет именно открытый канал, текст диалога называет его же |
| P1 | «Изменить лимит» передавал объект события вместо канала → запрос уходил на `/author-profiles/undefined` | Передаётся `activeChannel` |
| P1 | Пока сервер не ответил, на проде показывалась dev-форма входа (и гарантированно получала 400) | Dev-форма только при `dev_auth === true` |
| P1 | Закрытие окна согласия на AI (Esc/крестик) молча отменяло действие — кнопка выглядела нерабочей | Отмена продолжает действие без AI (правилами) |
| P1 | Свёрнутый аккордеон оставался в Tab-порядке: внутри ловились кнопки «Удалить» | `inert` + `aria-hidden` у закрытой панели |
| P1 | Любое исключение в рендере = пустой белый экран | `ErrorBoundary` с причиной, «Перезагрузить» и «На главную» |
| P1 | `window.open` бота после `await` мог быть заблокирован без сообщения | Показываем «браузер заблокировал окно — откройте ссылку вручную» |
| P2 | Поле палитры ⌘K без видимого фокуса | Вернули `focus-ring` |
| P2 | Подписи групп в сайдбаре — контраст ≈1.4:1 (ниже нормы) | Токен `--label-tertiary` (≈5:1) |
| P2 | Шрифты блокировали первый рендер; без JS — пустой экран | Неблокирующая загрузка шрифтов + `<noscript>` с объяснением |
| P2 | Класс `.row` использовался, но не был объявлен (правила AntiCringe «разъезжались») | Класс добавлен в стили |

**Отложено (записано в план, не забыто):** автосохранение черновика при уходе с
шага, ловушка фокуса в палитре и ящике, подтверждение при «Примере заметок» и
«Сбросе», скелетоны в настройках, ARIA-прогресс у визарда, «Повторить» для ошибки
генерации, лимиты длины текстовых полей, транзакция публикации, advisory-лок
миграций, ограничение источников/фактов на канал.
