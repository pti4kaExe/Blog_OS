# BlogOS — целевая версия 2.0

Инструмент для авторов каналов и блогов: собирает пост из сырых заметок в
авторском стиле, проверяет черновик на клише, логические ошибки и отклонения от
Tone of Voice, находит обсуждения для ответов и помогает ответить в своём стиле.

Версия 2.0 — это не прототип в браузере, а приложение целиком: React-клиент,
серверное API на **59 методов**, база **PostgreSQL 16 + pgvector** (14 таблиц) и
развёртывание на бесплатном хостинге.

## Чем 2.0 отличается от прототипа

| | Прототип 1.x | Целевая версия 2.0 |
|---|---|---|
| Где считаются движки | только в браузере | в браузере (локальный режим) и на сервере (облачный); одни и те же чистые движки из `@blogos/engine` |
| Данные | `localStorage` | PostgreSQL 16 + pgvector; `localStorage` остаётся офлайн-режимом |
| API | нет | 59 методов в 11 группах — контракт в [docs/API.md](docs/API.md) |
| Вход | нет | Telegram `initData` + JWT; dev-вход при `DEV_AUTH=1` |
| AI | только правила | правила всегда и бесплатно, LLM — второй слой: `mock` / `deepseek` / `openai`, лимит расходов на канал |
| RAG | нет | база знаний автора, векторы 1536 и HNSW-поиск |
| Внешние площадки | демо-данные | адаптеры Telegram / Instagram / YouTube: импорт постов и сканирование комментариев |
| Качество | 49 тестов движков | те же 49 тестов + тесты API на PGlite + Evals по `golden_dataset` |
| Запуск | `npm run dev` | PGlite без Docker и сети; Docker или Neon для настоящего PostgreSQL |
| Публикация | статика | Neon → Render → Vercel; плюс `Dockerfile` для любого контейнерного хостинга |

Поток работы прежний: **Стиль → Заметки → Пост → Проверка**, отдельная вкладка
**CommentRadar**. Меняется то, что результат можно сохранить на сервере, открыть
с другого устройства и получить проверку с участием LLM — при этом всегда остаётся
правиловый результат и отметка `verified_without_ai`, если модель недоступна.

## Требования

- **Node.js ≥ 22.18** (проверено на Node 24.13). Раньше нельзя: API исполняет
  TypeScript напрямую средствами Node (type stripping), без `tsx`, `esbuild` и
  отдельного шага сборки.
- npm 10+ (проверено на npm 11.8).
- Docker — не обязателен. Нужен только для настоящего PostgreSQL локально.
- Ключи внешних сервисов — не обязательны: по умолчанию `LLM_PROVIDER=mock`,
  `EMBEDDINGS_PROVIDER=mock`, база — PGlite.

## Быстрый старт без Docker (PGlite)

PGlite — это настоящий PostgreSQL 16 с pgvector, собранный в WASM. Схема, типы,
триггеры и `vector(1536)` те же, что на сервере; данные лежат в папке
`.pglite-data`. Сеть и Docker не нужны.

```bash
cp .env.example .env       # Windows PowerShell: Copy-Item .env.example .env
npm install                # 1. зависимости монорепо
npm run db:migrate         # 2. схема в PGlite: 14 таблиц
npm run dev:api            # 3. терминал 1 — API, http://localhost:3000
npm run dev:web            # 3. терминал 2 — клиент, http://localhost:5173
```

Адреса после запуска:

| Что | Адрес | Ожидаемый ответ |
|---|---|---|
| Клиент | http://localhost:5173 | интерфейс BlogOS |
| API | http://localhost:3000 | `{"name":"BlogOS API","version":"2.0.0","methods":59,...}` |
| Проверка живости | http://localhost:3000/health | `{"status":"ok","db":"ok","llm":"mock",...}` |

В рабочей копии `.env` уже есть; на чистом клоне его надо скопировать из
`.env.example` — без `DATABASE_URL` и `JWT_SECRET` сервер не стартует и печатает,
каких переменных не хватает. Повторный `npm run db:migrate` безопасен: уже
применённые файлы пропускаются по таблице `_migrations`.

`npm run dev:api` запускает сервер через `node --watch` (автоперезапуск). В
ограниченных средах, где запрещён запуск дочерних процессов, используйте
`node apps/api/src/server.ts` — тот же сервер без автоперезапуска.

Что попробовать:

- **Локальный режим** работает сразу и без API: конвейер и CommentRadar считаются
  в браузере, данные — в `localStorage` (`blogos.state.v1`).
- **Облачный режим** — переключатель в интерфейсе. Нужен запущенный API; пока в
  `.env` стоит `DEV_AUTH=1`, доступен dev-вход (`telegram_id` + имя) через форму
  входа или `POST /auth/telegram`. На проде `DEV_AUTH` обязан быть `0` — см.
  «Безопасность».

## Запуск на настоящем PostgreSQL

Способ выбирается одной переменной `DATABASE_URL`: `pglite://…` — WASM-база,
`postgresql://…` — обычный сервер PostgreSQL. Код приложения не меняется.

### Docker Compose (PostgreSQL 16 + pgvector)

```bash
docker compose up -d db
# в .env: DATABASE_URL="postgresql://blogos:blogos@localhost:5432/blogos"
npm run db:migrate
npm run db:seed        # демо-данные, необязательно
npm run dev:api
```

Docker-образ `pgvector/pgvector:pg16` уже включает расширение `vector`; схема в
контейнер не подкладывается — единственный путь её применения — `npm run db:migrate`.
Redis не обязателен; чтобы поднять его вместе с базой:
`docker compose --profile full up -d` и `REDIS_URL="redis://localhost:6379"` в `.env`.
Без Redis ограничитель частоты сканирований работает в памяти процесса.

### Neon (бесплатный хостинг PostgreSQL)

```bash
# DATABASE_URL="postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/blogos?sslmode=require"
npm run db:migrate
npm run db:seed        # только для демо-данных
npm run dev:api
```

В строке подключения обязателен `sslmode=require`; для миграций берите direct-
строку, для приложения — pooled (пулер Neon). Подробно — [docs/RUNBOOK.md](docs/RUNBOOK.md).

## Переменные окружения

Все серверные переменные проверяются схемой при старте: при ошибке процесс
завершается с перечнем проблем, а не падает через час на первом запросе.
Секреты живут только в окружении; `.env` в `.gitignore`, полный пример — `.env.example`.

### База данных

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_URL` | `pglite://.pglite-data` | Строка подключения. `pglite://…` — PGlite (WASM), `pglite://memory` — база в памяти для тестов, `postgresql://…` — настоящий PostgreSQL. На проде — Neon с `?sslmode=require`. |

### Сессии и вход

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `JWT_SECRET` | dev-значение | Секрет подписи токенов, ≥ 32 символов на проде. На Render генерируется автоматически (`generateValue`). |
| `DEV_AUTH` | `1` | `1` — принимает dev-вход (`telegram_id` + имя) вместо подписи Telegram. На проде обязательно `0`. |
| `TELEGRAM_BOT_TOKEN` | пусто | Токен бота из @BotFather: проверка подписи `initData` при входе из Telegram. |

### Нейросеть (LLM)

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `LLM_PROVIDER` | `mock` | `mock` — детерминированные ответы без сети и денег; `deepseek`; `openai` (совместимый формат). |
| `DEEPSEEK_API_KEY` | пусто | Ключ DeepSeek (только при `LLM_PROVIDER=deepseek`). |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | Базовый адрес DeepSeek. |
| `DEEPSEEK_MODEL` | `deepseek-chat` | Модель DeepSeek. |
| `OPENAI_API_KEY` | пусто | Ключ OpenAI (только при `LLM_PROVIDER=openai`). |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Базовый адрес OpenAI-совместимого API. |
| `OPENAI_MODEL` | `gpt-4o-mini` | Модель OpenAI. |
| `LLM_TIMEOUT_MS` | `45000` | Таймаут вызова; после таймаута — одна повторная попытка, затем откат на правила. |

### Эмбеддинги и RAG

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `EMBEDDINGS_PROVIDER` | `mock` | `mock` — детерминированные векторы 1536; `openai` — настоящая модель; `none` — без векторов. |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Модель эмбеддингов; её размерность зафиксирована в схеме. |
| `EMBEDDING_DIM` | `1536` | Размерность вектора. Меняется только вместе с миграцией колонки `embeddings.embedding`: `vector(1536)`. |
| `RAG_TOP_K` | `5` | Сколько фрагментов возвращает поиск по базе знаний. |

### Расходы на AI

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `COST_WARN_RATIO` | `0.8` | Доля месячного лимита канала, после которой автор видит предупреждение; на `1.0` AI-вызовы блокируются, а проверка идёт на правилах. |

### Сервер

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `3000` | Порт API. Render передаёт свой порт автоматически. |
| `HOST` | `0.0.0.0` | Адрес прослушивания. |
| `CORS_ORIGIN` | `http://localhost:5173,http://127.0.0.1:5173` | Список разрешённых источников через запятую (схема + домен, без слэша на конце). `*` разрешает все — только для демо. |
| `LOG_LEVEL` | `info` | Уровень логов (`info` в проде, `debug` при разборе проблем). |
| `REDIS_URL` | пусто | Необязательный Redis: общий ограничитель частоты сканирований. Пусто — ограничитель в памяти процесса. |

### Клиент

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VITE_API_URL` | `http://localhost:3000` | Базовый адрес API для клиента. Задаётся в `apps/web/.env.local` локально и в настройках Vercel для прода; встраивается в бандл при сборке, поэтому после изменения нужна пересборка. |

Дополнительно сервер читает переменные адаптеров площадок (`TELEGRAM_API_BASE`,
`INSTAGRAM_GRAPH_BASE`, `INSTAGRAM_ACCESS_TOKEN`, `YOUTUBE_API_BASE`,
`YOUTUBE_API_KEY`). В `.env.example` их нет: значения по умолчанию указывают на
официальные API, а пустой ключ означает «адаптер не настроен» (ответ
`503 not_configured`, остальные функции работают).

## Режимы работы

| Режим | Где считаются движки | Где данные | Вход | Сеть |
|---|---|---|---|---|
| Локальный | в браузере | `localStorage` (`blogos.state.v1`) | не нужен | не нужна |
| Облачный | на сервере (`@blogos/engine` + LLM); браузер показывает результат | PostgreSQL + pgvector | Telegram или dev-вход; JWT 30 дней | нужна |

Локальный режим — не заглушка: это тот же правиловый движок, что и на сервере.
Если API недоступен, приложение не падает, а продолжает работать локально.
В облачном режиме данные (каналы, стиль, посты, черновики, отчёты, источники,
база знаний, расходы) сохраняются в базе и доступны с другого устройства.

| AI-режим | Как включается | Поведение |
|---|---|---|
| `mock` (по умолчанию) | `LLM_PROVIDER=mock`, `EMBEDDINGS_PROVIDER=mock` | Детерминированные ответы, без сети и денег; тесты, CI и демо работают всегда. |
| DeepSeek | `LLM_PROVIDER=deepseek` + `DEEPSEEK_API_KEY` | Дешёвые вызовы, модель `deepseek-chat`. |
| OpenAI | `LLM_PROVIDER=openai` + `OPENAI_API_KEY` | Совместимый API, модель `gpt-4o-mini`. |

Правила работают всегда и бесплатно, LLM — второй слой. При таймауте или ошибке —
одна повторная попытка, затем откат на правила с `verified_without_ai: true` и
`engine: "rules"`; каждый вызов пишется в `generation_runs`. На 80% месячного
лимита канала автор видит предупреждение, на 100% AI-вызовы блокируются
(`402 ai_budget_exceeded`), но проверка текста продолжается на правилах.

## 59 методов API

Контракт — [docs/API.md](docs/API.md) (единственный источник истины для сервера,
клиента и тестов); машинночитаемая версия — [docs/openapi.yaml](docs/openapi.yaml)
(OpenAPI 3.1). Методы доступны и в корне (`/auth/telegram`), и по алиасу
`/api/v1/...` — второй вариант нужен при развёртывании за статическим хостом.
Аутентификация — `Authorization: Bearer <jwt>`; ошибки — единый конверт
`{error: {code, message, details}}`; списки — курсорная пагинация (`limit` 50,
максимум 200).

| № | Группа | Методов | Назначение |
|---|---|---|---|
| 1 | Вход и пользователь | 4 | Telegram `initData`, профиль, удаление аккаунта |
| 2 | Каналы | 6 | CRUD `author_profiles`, расходы канала (`usage`) |
| 3 | Стиль | 3 | Профиль Tone of Voice: чтение, `PUT`, анализ текстов |
| 4 | Посты | 6 | Архив постов, импорт с площадки с дедупликацией |
| 5 | Черновики | 7 | CRUD, Narrative Engine (`generate`), публикация в архив |
| 6 | Проверка | 3 | AntiCringe: `lint`, история отчётов, отчёт по id |
| 7 | Источники | 5 | Отслеживаемые каналы для CommentRadar |
| 8 | Комментарии | 6 | Ручное добавление, сканирование площадки, CRUD |
| 9 | Варианты ответа | 6 | Генерация из четырёх частей, статусы, одобрение |
| 10 | База знаний | 6 | Факты автора, RAG-поиск по векторам |
| 11 | Служебные | 7 | Журнал расходов, `golden-dataset`, Evals |
| | **Итого** | **59** | **11 групп** |

Схема базы: 14 таблиц, 17 внешних ключей, каскадное удаление и `SET NULL` для
журнала расходов, триггеры `updated_at`, неизменяемость `lint_reports`,
HNSW-индекс для косинусного поиска.

## Деплой: Neon → Render → Vercel

Схема: клиент — статика на Vercel, API — Node на Render, база — Neon
(PostgreSQL 16 + pgvector). Клиент обращается к API напрямую по HTTPS, API — к
базе по SSL. Порядок важен: сначала база и миграции, потом API, потом клиент.
Пошаговая инструкция с проверками и лечением ошибок — [docs/RUNBOOK.md](docs/RUNBOOK.md).

| Шаг | Сервис | Что делает | Конфигурация |
|---|---|---|---|
| 1 | **Neon** | PostgreSQL 16 + pgvector, миграции `npm run db:migrate` с локальной машины | `DATABASE_URL` c `?sslmode=require` |
| 2 | **Render** | API (`node apps/api/src/server.ts`), проверка живости `/health` | `render.yaml` |
| 3 | **Vercel** | Статическая сборка клиента, SPA-переписывание маршрутов | `vercel.json` |

Бесплатные тарифы и их особенности (проверяйте актуальные лимиты у провайдеров —
они меняются):

- **Neon free** — 1 ГБ хранилища на проект, 100 CU-часов вычислений в месяц;
  вычисления останавливаются через 5 минут простоя (первый запрос после паузы
  медленнее), история восстановления — 6 часов. Есть пулер соединений: для
  приложения берите pooled-строку, для миграций — direct.
- **Render free** — web service засыпает после ~15 минут без запросов и
  просыпается около минуты; 750 часов инстансов в месяц; откат доступен только
  к двум последним предыдущим деплоям. Для демонстрации API нужно прогреть заранее.
- **Vercel Hobby** — бесплатная статика в пределах лимитов тарифа: одна
  параллельная сборка, до 45 минут на сборку, 100 деплоев в сутки; API и база
  там не размещаются.

Прогрев перед показом (заодно будит вычисления Neon — `/health` делает `SELECT 1`):

```bash
curl -s https://<ваш-сервис>.onrender.com/health
# {"status":"ok","db":"ok","version":"2.0.0",...}
```

Холодный старт Render может ответить таймаутом или 502 — повторите запрос через
минуту. Миграции на Render free не запускаются автоматически (у free-плана нет
`preDeployCommand`): применяйте их вручную до деплоя, на платном плане можно
раскомментировать `preDeployCommand` в `render.yaml`.

Клиент Vercel собирается с `VITE_API_URL=https://<ваш-сервис>.onrender.com`
(переменная встраивается при сборке, после изменения нужен redeploy), а в
`CORS_ORIGIN` на Render указывается домен клиента, например
`https://blogos.vercel.app`. Внешний прокси `/api` через `rewrites` в
`vercel.json` не нужен: клиент ходит на API напрямую; при желании его можно
добавить, но тогда прокси-правило ставится до SPA-правила и домен API надо
обновлять вручную.

Есть и контейнерный путь: `Dockerfile` (multi-stage, `node:22-alpine`,
`npm ci --ignore-scripts`) собирает образ с API; миграции и сиды запускаются
отдельными командами вроде
`docker run --rm --env-file .env blogos-api node apps/api/scripts/migrate.ts`.

## Безопасность

- **Ключи — только в переменных окружения.** В репозитории нет ни ключей, ни
  `.env` (он в `.gitignore`). Ключи LLM, токен Telegram и строку подключения
  задавайте в Render/Neon, а не в коде.
- **`DEV_AUTH=0` на проде.** При `1` API принимает вход по паре
  `telegram_id` + имя без подписи — это режим локальной проверки.
- **`JWT_SECRET` случаен и длинен** (≥ 32 символов). На Render генерируется
  автоматически; смена секрета отзывает все открытые сессии.
- **CORS — список конкретных доменов.** `*` допустим только на время демо:
  он разрешает любому сайту обращаться к API от имени пользователя.
- **Тексты автора уходят внешнему LLM.** При `LLM_PROVIDER=deepseek/openai`
  фрагменты черновика, комментарии и база знаний отправляются в API провайдера.
  `mock` ничего не отправляет. Клиент предупреждает о передаче текста перед
  первым AI-вызовом; отказ передаётся как `use_llm: false`, и проверка идёт на
  правилах. Согласие хранится в браузере (`localStorage`) — поля в схеме нет,
  это открытый пункт (см. [docs/DECISIONS.md](docs/DECISIONS.md), решение № 28).
- **Публикация не отправляет посты на площадки.** `POST /drafts/{id}/publish`
  только фиксирует факт публикации в архиве: BlogOS не действует от имени автора
  на площадке.
- **Логи не содержат секретов**: заголовки `Authorization`/`Cookie` вырезаются,
  внутренние тексты ошибок наружу не отдаются.

## Известные ограничения и открытые вопросы

- **Проверка развёртывания не выполнялась в среде подготовки**: конфигурации
  Render/Vercel/Docker написаны и проверены статически и локальными командами,
  но реальные деплой, сборка Docker-образа и внешние API отсюда недоступны.
- **PGlite — для локального запуска и тестов**, не для продакшена: файл базы в
  рабочей папке, одно соединение, нет общей работы нескольких инстансов. На
  хостинге используйте PostgreSQL.
- **Instagram и YouTube**: адаптеры написаны, живые ключи и условия API
  (Business-аккаунт, квоты) не проверены — без ключей методы отвечают
  `503 not_configured`.
- **LLM-провайдер**: условия хранения текстов у DeepSeek/OpenAI нужно прочитать
  до продакшена; стоимость считается по прайсу в коде и требует сверки.
- **Redis не обязателен**: без него ограничитель частоты сканирований живёт в
  памяти одного инстанса.
- **Миграции только вперёд**: обратных миграций нет; откат схемы — через ветку
  или восстановление Neon (см. RUNBOOK).
- **Роль `admin` выдаётся вручную в базе** — метода назначения роли нет намеренно.
- **Интерфейс настройки правил AntiCringe** не реализован (решение № 14);
  настраиваемые стоп-слова хранятся в `tov_profiles.stop_words`.

Полный список решений и открытых пунктов — [docs/DECISIONS.md](docs/DECISIONS.md).
